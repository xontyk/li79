# Сайт Лицея-интерната №79

Многостраничный сайт лицея-интерната с закрытой админ-панелью. Реализовано по
техническому заданию: публичные страницы (главная, о лицее, обучение,
поступающим, жизнь лицея, учителя, олимпиадники, вакансии, контакты) и
админ-панель с регистрацией/одобрением администраторов, CMS-редактированием
страниц и CRUD-разделами «Учителя» и «Олимпиадники» с автосжатием фото.

## Стек

- PHP 8+ (без фреймворков, только расширения `pdo_mysql` и `gd`)
- MySQL 5.7+/MariaDB
- HTML5 / CSS3 (Flexbox, Grid, медиа-запросы) / vanilla JS

## Установка (локально или на боевом сервере)

1. **База данных.** Создайте базу данных и импортируйте схему:

   ```sql
   CREATE DATABASE licey79 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

   ```bash
   mysql -u ВАШ_ЛОГИН -p licey79 < sql/schema.sql
   ```

   Скрипт создаёт таблицы (`admins`, `teachers`, `olympiad_winners`, `pages`,
   `contact_messages`), базовый контент для всех 9 страниц, несколько примеров
   учителей/олимпиадников и **первого администратора**:

   - логин: `xontyk@gmail.com`
   - пароль: задан разработчиком при настройке (в файле не хранится в открытом виде)

   ⚠️ **Рекомендуется сменить пароль напрямую в БД после переноса сайта на
   боевой сервер** — хэш пароля лежит в `sql/schema.sql`, а значит и в истории
   репозитория. Проще всего сменить его так:

   ```sql
   UPDATE admins
   SET password_hash = '<результат password_hash() для нового пароля>'
   WHERE email = 'admin@licey79.ru';
   ```

2. **Настройки подключения.** Отредактируйте константы в `config.php`
   (или задайте одноимённые переменные окружения на хостинге):
   `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`.

3. **Права на запись.** Веб-сервер должен иметь право создавать файлы в папке
   `uploads/` (для загружаемых и автоматически сжимаемых фотографий).

4. **Локальный запуск для проверки:**

   ```bash
   php -S localhost:8000
   ```

   и открыть `http://localhost:8000/`.

## Как это устроено

### Публичные страницы

Каждая из 9 страниц карты сайта хранит свой текстовый контент в таблице
`pages` (поле `content`) и подключает общие `includes/header.php` /
`includes/footer.php`. Учителя (`teachers.php`) и олимпиадники
(`olympiad.php`) выводятся из одноимённых таблиц — без правки HTML.

Любая новая страница, добавленная в админ-панели, автоматически появляется
в меню сайта и открывается по адресу `/page.php?slug=<её-адрес>`.

### Админ-панель

- **Регистрация → одобрение.** Новый администратор регистрируется
  (`admin/register.php`) со статусом `pending`, видит страницу
  `admin/pending.php` и не может войти, пока другой одобренный администратор
  не примет заявку в разделе «Заявки на доступ» (`admin/requests.php`).
- **CRUD «Учителя» / «Олимпиадники».** Стандартные формы добавления,
  редактирования и удаления (`admin/teachers*.php`, `admin/olympiad*.php`).
- **Конструктор страниц.** В разделе «Страницы сайта» (`admin/pages.php` →
  `admin/page-edit.php`) содержимое собирается из блоков — как в конструкторах
  сайтов (Tilda и т.п.), а не редактируется одним полем с HTML. Доступные
  блоки: заголовок, текст (с мини-редактором Quill — жирный/курсив/ссылка),
  фото (с drag-and-drop загрузкой), кнопка, цитата, список. Блоки можно
  добавлять, удалять и менять местами (стрелки ↑/↓) — весь интерфейс на
  `js/page-blocks-editor.js`. Можно создать новую страницу (адрес формируется
  автоматически из названия транслитерацией в латиницу) или удалить — кроме
  служебных страниц «Главная» и «Контакты».

  Технически содержимое страницы (`pages.content`) хранится как JSON-массив
  блоков; функции `render_page_blocks()` / `sanitize_page_blocks()` /
  `decode_page_blocks()` в `includes/functions.php` отвечают за вывод на
  сайте, проверку при сохранении и разбор для редактора соответственно.
  Старое содержимое (сплошной HTML, как было в первой версии сайта)
  автоматически распознаётся и показывается отдельным блоком «Старый блок
  (HTML)», который можно отредактировать или заменить новыми блоками —
  ничего не теряется при обновлении.
- **Фото.** При загрузке фото учителя, а также при вставке фото в блок
  страницы (`admin/upload-image.php`), сервер проверяет формат (JPG/PNG/WebP)
  по реальному MIME-типу файла и, если высота больше 720px, пропорционально
  сжимает изображение через GD (`includes/functions.php →
  upload_and_resize_image()`). Оригинал большого размера не сохраняется.
  Библиотека Quill подключена локально из `js/vendor/quill/` и
  `css/vendor/quill/` — интернет на боевом сервере для её работы не нужен.

### Безопасность

- Пароли хранятся только в виде хэша (`password_hash()` / `password_verify()`).
- Все запросы к БД — через подготовленные выражения PDO (без конкатенации
  значений в SQL).
- Каждая страница `admin/*.php` (кроме входа/регистрации) вызывает
  `require_login()`, которая проверяет сессию и иначе перенаправляет на вход.
- Все формы, изменяющие данные, защищены CSRF-токеном
  (`csrf_field()` / `check_csrf()`).
- Ошибка входа не уточняет, какое именно поле неверно.
- Папка `uploads/` закрыта от исполнения скриптов через `.htaccess`
  (актуально для Apache; при переносе на nginx добавьте аналогичное правило
  в конфигурацию сервера — запретить выполнение `.php` внутри `/uploads/`).

## Тестирование

Все PHP-файлы проверены на синтаксис (`php -l`). Полный сценарий —
регистрация администратора → заявка ожидает одобрения → одобрение → вход;
CRUD учителей с загрузкой и автосжатием фото (1200×1600 → 540×720);
CRUD олимпиадников; создание/редактирование/удаление страниц с защитой
служебных страниц «Главная» и «Контакты» — проверен вручную через
встроенный веб-сервер PHP с тестовой базой данных.

Так как в среде разработки недоступен сервер MySQL, финальную проверку с
реальной базой данных MySQL/MariaDB стоит провести на целевом хостинге перед
сдачей проекта.

## Известные упрощения

- Фотогалерея на странице «Жизнь лицея» использует несколько статичных

  страницы через `admin/page-edit.php`.
